# 影格表與預覽

確認成品播放時間與統一縮放倍率。`loop` 預設等距取樣 8 格（來源不足時取可用張數）；兩種單次動作預設依局部姿態差異自適應張數，不先指定 8 或 12 格。以少量影格保留動作可讀性、中間姿態與來源節奏，不能只靠張數宣稱品質。

本段只接收來源影片、圖片工作流設定、Refine 提示詞與明確處理參數，不讀取前段角色版面或生成提示詞。先確認角色與裝備仍可辨識；完全被不透明效果取代的內容不保證能重建，需要時換區間或回報來源不足，不在後段重新設計角色。

## 動作類型與區間

| 類型 | 參數／英文名稱 | 定義與選段 |
| --- | --- | --- |
| 循環動作 | `loop` / Loop | 末尾可直接銜接開頭。找動作極接近的頭尾，尾端減一來源格，避免重複接點；必須有實際運動，不把靜止片段當循環。 |
| 返回起始動作 | `return_to_start` / Return to start | 完成一次動作後回到同一起始基準，可再次觸發。若有穩定段，頭取起始穩定段最後一格，尾取返回穩定段第一格；保留相近兩端。沒有穩定段時改找相近姿態候選，仍須確認涵蓋完整動作，不能只取中途往返。 |
| 保持結束姿態動作 | `hold_end_pose` / Hold end pose | 完成一次動作後停在目標姿態。先找最後穩定段的第一格 D，再向前找主要動作前最後穩定段的最後一格 B，得到主要動作 Y＝B..D；再檢查 B 之前有無有意義演出 X。 |

起始基準由任務環境決定，地面是對應 Idle，空中是對應空中姿態；不是影片第 0 格，也不要求每個交付片段從 Idle 開始。GIF 一律無限重播，JSON 的 `loop` 表示動作循環性，不控制 GIF 重播。

Python 的 `select_segment.py` 以低解析度數值分析提出候選，並保存 `auto-segment.json`。`status=selected` 不等於視覺通過。無明確結果時，Codex 檢查必要的候選預覽並指定 `--start`、`--end`；不可套固定秒數或所有影片共用同一區間。索引從 0 起算，包含 end。手動 loop 的 end 也應已排除重複接點，程式不再減一次。

### hold_end_pose 的 X 與 Y

B 的判斷用穩定程度及主要動作的開始，不由自適應補幀分數推導。Y 明確為 B..D，不能把前段 A 混入 Y，再由去重間接刪掉 A..B 的演出。

Codex 在 Refine 前檢視 B 之前必要的局部候選，辨識有意義前段演出的起點 A；排除開場 Idle、姿態準備及無關等待。這是內容判斷，不按動作名稱分流，不要求 Codex 逐幀看完整影片。自動選段的 `lead_candidate_range` 只是待檢查範圍，不能直接當 X。

- 有 X：明確給 `--lead-start A --start B --end D`，X 為 A..B−1，Y 為 B..D，B 只出現一次。
- 沒有 X：檢查後明確給 `--lead-start B`。省略時仍可輸出 Y，但 `sampling.lead_review_required=true`，Codex 不可因此略過前段檢查或直接標記交付完成。
- X 保留少量小動態。時間分箱先選代表姿態，再將顯著變化補在原時間箱內；確實靜止時只留一張代表格，不用重複圖填滿張數。`--lead-refresh-ms` 預設 160，控制代表圖的取樣節奏，並非固定 X 時長，可依選中預覽調整。數值不是跨素材品質保證。
- `--count` 若指定，只控制 Y 張數，X 另計；不把 X 擠入主要動作的張數預算。

```text
python scripts/spritesheet.py source.mp4 --motion-type hold_end_pose --lead-start A --start B --end D --seconds 1 --scale RESTORE_SCALE --output work/action/selection
python scripts/finish_animation.py source.mp4 --motion-type hold_end_pose --lead-start A --start B --end D --seconds 1 --scale RESTORE_SCALE --image-profile .local/image-profile.json --job work/action/finish-job --output outputs/action --prompt-file work/action/refine.txt
```

## 依動作類型選幀與保留節奏

`loop` 與未指定類型的手動區間維持等距取樣；跳躍拆出的上升、下落段也維持各段等距，見[空中處理](airborne.md)。

`return_to_start` 與 `hold_end_pose` 的 Y 使用 `scripts/frame_sampling.py`，地面與空中共用：

1. 在已確認區間，以來源幀率解碼低解析度數值特徵；不是把整段送去圖片編輯或 Codex 逐幀判讀。移除區間共同靜態特徵，忽略不大於 4 的特徵強度差，以減少不變身體與微量雜訊稀釋局部動作。
2. 先保留頭尾。對每個相鄰已選區間，計算內部格與左右端點的正規化差異，兩者較小值是補幀價值；選最大的候選分割區間，再遞迴比較。相同分數以鄰格變化與時間位置決定順序。
3. 當所有局部候選分數均不超過門檻便停止，不會每次呼叫都強制補一格。`--quality compact`（預設）門檻 0.75，`balanced` 0.60，`smooth` 0.45；較低門檻選得較密。這些是經素材測試的操作預設，不是動作品質、人體軌跡或成功機率。
4. 明確指定 `--count N` 時改為指定張數，仍按同一分割優先順序補選，保留首尾；僅在使用者要求或實際檢查有依據時使用，不能再次一律固定 8 格。來源張數不足即停止，不複製影格湊數。

演出效果可提供出力線索，數值分析不一律排除它；特效、衣物、鏡頭與位移也可能干擾。空中取樣在腰部定位之前，須確認沒有只追隨垂直移動而漏掉肢體。這不是主要目標追蹤器，不能保證自動分辨主動作與伴隨動作。

### Refine 前的少量視覺檢查

先用 `spritesheet.py` 輸出 `selection.json` 與 `cropped/`，檢視選中影格及必要的局部候選：

- 區間涵蓋起手、主要展開與收招；動作結束符合類型。
- 快速過程與必要中間姿態仍可讀；不是多張近似姿態佔位卻漏掉主要過程。
- 去掉效果後角色與裝備本身能交代動作；X 是有意義演出而非前置準備。
- X 小動態、主要動作與接點節奏合理；預覽逐支獨立觀看，避免拼成同步比較動畫干擾判讀。

先修正區間，再按證據調整 quality、X 取樣節奏或明確張數，不改共用程式遷就某支素材。確認後以相同參數執行 `finish_animation.py`。要鎖定手選索引，可使用 `spritesheet.extract_frames`、`prepare_frames` 與 `finish_animation.finish_prepared`；將 scripts 加入 Python 匯入路徑，保存真實索引、判斷與 `sampling.frame_durations_ms`。CFR 明確索引可用 `source_weights`，影片取樣則使用 `source_clock.FrameClock` 的實際時間戳，按相鄰代表格時間中心中點分配來源覆蓋。

### 共用來源時間倍率

選幀密度與時間分開。`source_clock.py` 讀來源影格 PTS 與最後一格長度；X 時間為 t(B)−t(A)，Y 為 t(D+1)−t(B)。只使用有效 A..D，不把排除的 Idle 或過長尾端停留算進比例。沒有 X 時使用 B..D。

整段依 `--seconds` 使用一個倍率。GIF 採 20 ms 網格，要求秒數向下取至此網格；X 按比例向下取整，不超過其比例時間，餘數給 Y。每格至少 20 ms，補選只分攤原時間，不增加 X、Y 或總長。時間不足容納影格時停止，改選較省格策略或依使用者時間需求處理，不能暗中拉長動畫。來源 X 本身很長時，其占比仍會保留，比例規則不等於自動改善來源演出。

`animation.json` 的 `sample_indices`、`frame_durations_ms` 與影格表順序對應，`sampling` 保存局部分割分數、停止原因、來源時間、X/Y 分界及預算。GIF 使用同一時間表；Refine、去背、裁切與空中腰部定位不得重選或改寫時間。交付時提醒使用者在引擎使用逐格時間，否則等時長播放會改變非等距選幀的節奏。程式時間檢查不能取代實際 GIF 檢視。

## 裁切、Refine 與合併

`--scale` 預設 1，是所有選中影格的統一縮回倍率。後端不讀取前端基準框、站姿或留白設定。使用者直接提供影片而需要限制交付格子大小時，可另用 `--max-side`；按既定角色尺度縮回時省略它。

將 Refine 提示詞存為 UTF-8 檔案。提示詞應要求清除影片額外生成、最終角色動畫不需要的視覺效果，修復動態模糊及角色輪廓與細節，並同時移除背景、輸出真正透明 PNG。半透明覆蓋區需去掉造成的灰霧、亮度及色彩污染，恢復仍可辨識的角色內容。保持原影格的角色外觀、繪製風格、朝向、姿勢、配件、尺度、位置與畫布尺寸；依素材辨識多餘內容，不將特定效果或動作寫成程式規則。武器、握柄及其原有裝飾屬於實體裝備，與待移除效果分開辨識，保留完整刃線、尖端、握持關係與表面細節。不要移除角色本身的設計元素，也不要改變肢體姿勢或新增細節。

可依素材調整下列提示詞：

> 清理這張角色動畫影格，移除額外生成的視覺效果與背景，清除半透明覆蓋造成的灰霧、亮度與色彩污染；修復動態模糊，恢復清晰且符合原繪製風格的輪廓與細節。保留角色身份、服裝、配件、實體裝備、朝向及當前動作姿勢，保持角色尺度、畫布內位置及畫布尺寸不變。保留可見肢體、裝備的細長輪廓與尖端，以及手部握持關係。輸出保留完整角色與半透明邊緣的透明背景 PNG。

Python 只分析選中影格，從各格外框取樣估計實際純色背景，再依色差閾值取得內容範圍；預設閾值為各 RGB 通道最大差 32，可用 `--background-tolerance` 調整。

第一次共同裁切以統一縮放後的畫面中線為水平中心，左右對稱容納所有選中影格的內容，上下涵蓋共同範圍。所有影格以相同座標裁切並保存至任務目錄 `cropped/`；此時視覺效果也可能包含在裁切範圍內。

裁切後依原順序逐張執行圖片工作流，同一份提示詞同時進行 Refine 與去背。各張任務位於 `refine/000/image-job/` 等獨立目錄，保存輸入、工作流、任務狀態及結果。圖片尺寸倍數由 profile 的 `input_alignment` 決定，只在每張右側、底部補原背景，處理後裁回原尺寸，不改變角色位置與尺度。

每張結果必須保持送入尺寸、具備真正透明背景與有效可見角色；尺寸變更、不透明或空白結果會停止處理，不自動跳過。用相同命令與任務目錄重跑可重用已完成的逐張工作流，接續未完成任務；輸入、提示詞或 profile 變更時須使用新任務目錄。提交沒有取得 ID 時，先查佇列，不直接重送。

Refine 後先清除低 Alpha 殘值，再計算第二次共同裁切。`--alpha-cutoff` 預設為 8：Alpha 小於 8 清為 0，8 以上保留原本漸層與 RGB，不強制二值化；設為 0 可停用清理，合法範圍為 0～255。含極淡半透明設計的角色需檢視原始 Refine 結果，必要時降低門檻。所有影格清理後以非零 Alpha 範圍計算共同裁切框，完整容納保留下來的邊緣；若最終縮放重新產生低 Alpha 像素，交付前會再次以同一門檻清理。原始 Refine PNG 保留不變，清理作用於最終影格。以原裁切畫布中線為水平中心，左右對稱，上下涵蓋所有角色內容；每張使用相同座標，不逐幀置中、貼底或縮放。若指定 `--max-side`，只在此時使用共同倍率限制最終尺寸。最後各張底部補 1 px 透明邊，保存至 `final-frames/`，再合併影格表。

1 至 6 格單排，7 至 12 格雙排，13 格以上每排最多 6 格並增加排數。順序為左至右、上至下，未用格子透明。

輸出為 `spritesheet.png`、`preview.gif`、`animation.json`。規格包含來源影格索引、逐格播放時間、取樣策略、統一縮放倍率、第一次裁切、逐張處理素材與補邊、第二次 Alpha 裁切、`refined_crop.alpha_cutoff` 及最終格子尺寸。兩次裁切框分別使用縮放後影片與 Refine 畫布的座標。成品總播放時間獨立於來源影片速度，區段內節奏依上節處理；GIF 的 Alpha 小於 128 設為透明，其餘不透明，PNG 保留完整 Alpha。

Codex 最後對照選中來源、原始 Refine 及 Alpha 清理後成品，確認多餘效果已移除、模糊已修復，並檢查姿勢、外觀、尺度及位置的一致性。武器須逐格確認刃線、尖端、握柄與手部連接沒有被當成特效刪除；細髮、飄帶與半透明設計也須比較 Alpha 清理前後。程式尺寸與 Alpha 檢查不能代替視覺檢查；發現漂移時調整提示詞並在新任務中處理，不以逐幀重新定位掩蓋問題。若缺失已存在於原始 Refine，調整圖片編輯提示詞；若僅發生於低 Alpha 清理後，降低 `--alpha-cutoff` 並重製，不需要重新生成影片。

多個動作各自選區間、計算裁切框，使用獨立工作目錄與輸出目錄執行完整流程。每個動作各交付一張透明影格表與一張透明 GIF。

交付時以 `scripts/package_delivery.py --manifest assets.json --output delivery.zip` 打包；清單明確提供 `video`、`animation`（成品 JSON）及 `files`（封存內相對路徑對應素材路徑）。收集上傳圖、實際使用的姿態參考及 Idle 基準影格、影片輸入與提示詞，程式匯出全部與選中原始影格，並自動封存第一次裁切影格、逐張工作流輸入、Refine 透明影格、最終裁切影格及成品。實際 Refine 提示詞需由 `files` 明確收錄，例如 `"prompts/refine.txt": "work/action/refine.txt"`。只收集實際使用的素材，不猜前端目錄。聊天中直接展示 GIF 與透明影格表，附 ZIP 下載。

## 完成與交付驗證

### 檢查紀錄

各任務在自己的工作目錄保存 `review.md`，記錄目前有效的檢查結論；重做後更新當前結論，不累積修改歷史。角色參考準備也使用相同格式。這是 Codex 的檢查紀錄，不是後段腳本必填輸入，也不要求既有影片使用者補建前段紀錄。

```text
任務／階段：本次任務識別與檢查階段
檢查對象：實際檔案路徑；涉及選幀時列原始影格索引
項目 | 結果（pass / fail / pending / n/a） | 證據與判斷
下一步：未通過或待檢項目的處理；全部通過則寫可進入的下一階段
```

依實際階段列項，不抄一張全部通過的空泛清單：參考階段記錄姿態、外觀、完整性、透明與共用幾何；影片階段記錄演出、結束行為、節奏及超框／遮擋；空中定位階段記錄腰部匹配與位移；交付階段逐項記錄下列三類完成條件。證據可引用程式報告、實際檔案、接點或選中影格的具體觀察。視覺項目須實際開啟對應圖片或預覽，不以程式回報代替；尚未看過寫 `pending`，不適用寫 `n/a` 並說明原因。使用者已確認的項目註明確認內容；不為填表新增使用者問答。

只有本次必要項目均為 `pass`，其餘均有合理的 `n/a` 原因，才能宣告該階段通過。局部通過不代表整項完成。完成交付驗證後，可在角色計畫的 artifacts 另以 `review` 指向紀錄；沒有角色計畫時仍保存於本次工作目錄。

### 完成條件

程式回報成功、檔案存在或 JSON 中的 `verified` 均不能單獨代表任務完成。Codex 須在標記 `completed` 前完成以下檢查：

1. **格式與規格**：來源影片可讀，PNG、GIF、JSON 均可開啟；影格數、排列、格子尺寸、播放時間、動作類型及來源索引符合本次任務，JSON 路徑能解析到正確素材。PNG 有真正透明背景；GIF 預覽包含動作影格並設為無限重播，不可只播放一次。
2. **視覺品質**：依上文對照選中的來源影格、原始 Refine 與最終影格，檢查動作完整性、角色及裝備保留、透明邊緣、尺度與位置；循環接點或動作結束方式符合所選類型。只針對選中影格檢視，不將整段影片的所有來源影格送去 Refine 或視覺逐幀判讀。
3. **交付完整性**：確認 PNG、GIF、JSON、ZIP 實際存在且可供使用者取得；ZIP 可正常解壓，包含本任務實際使用的必要素材、提示詞與成品，封存內 JSON 路徑可使用。展示預覽並提供成品及 ZIP 的有效路徑或下載入口。

程式負責可機械檢查的格式、尺寸、Alpha、時間與封存完整性；Codex 負責動作意圖、視覺品質及交付內容的確認。任一必要檢查失敗或尚未完成，保留 `needs_review` 並說明待處理項目，不以檔案存在代替完成。全部通過後，再由角色計畫的 `mark` 記錄完成；直接提供影片而沒有角色計畫時，仍遵守相同交付條件。
