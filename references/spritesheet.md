# 影格表與預覽

真人 CFR 的 return_to_start／hold_end_pose 優先使用[正式姿態選幀](pose-sampling.md)；選段、主要姿態、遮擋補充、節奏補幀與時間表由同一次 execution_plan run 完成。下述外觀取樣仍適用於明確選用該方法的任務；不要因缺少姿態依賴而靜默切換，或將真人方法套到尚未驗證的畫風／影片類型。

確認成品播放時間與統一縮放倍率。`loop` 預設等距取樣 8 格（來源不足時取可用張數）；兩種單次動作預設依局部姿態差異自適應張數，不先指定 8 或 12 格。以少量影格保留動作可讀性、中間姿態與來源節奏，不能只靠張數宣稱品質。

正式執行使用 [執行計畫](execution.md) 的 selection → finish → package 階段；以下定義後段參數、提示詞與驗證。既有影片可直接 create-video。

本段只接收來源影片、圖片工作流設定、所需 Refine 提示詞與明確處理參數，不讀取前段角色版面或生成提示詞。先確認角色與裝備仍可辨識；完全被不透明效果取代的內容不保證能重建，需要時換區間或回報來源不足，不在後段重新設計角色。

## 動作類型與區間

| 類型 | 參數／英文名稱 | 定義與選段 |
| --- | --- | --- |
| 循環動作 | `loop` / Loop | 先辨識完整循環區段，再從各段擇優；所選尾端減一來源格，避免重複接點。必須有實際運動，不把靜止片段當循環。 |
| 返回起始動作 | `return_to_start` / Return to start | 完成一次動作後回到同一起始基準，可再次觸發。若有穩定段，頭取起始穩定段最後一格，尾取返回穩定段第一格；保留相近兩端。沒有穩定段時改找相近姿態候選，仍須確認涵蓋完整動作，不能只取中途往返。 |
| 保持結束姿態動作 | `hold_end_pose` / Hold end pose | 完成一次動作後停在目標姿態。先找最後穩定段的第一格 D，計算此前各活動區段高於穩定噪聲的累積能量；依能量由高到低的累積占比減區段數占比之最大轉折，保留主要活動集合。取集合中最早活動前方穩定段的最後一格 B，得到主要動作 Y＝B..D，包含中間停頓及收尾，不只取最大能量的末段。再檢查 B 之前有無演出 X；若 B 前全部屬開場穩定段，程式可判定無獨立 X，令 A=B，否則保留前段審查。 |

起始基準由任務環境決定，地面是對應 Idle，空中是對應空中姿態；不是影片第 0 格，也不要求每個交付片段從 Idle 開始。GIF 一律無限重播，JSON 的 `loop` 表示動作循環性，不控制 GIF 重播。

Loop 在來源中搜尋共同姿態基準的顯著離開及返回，連續返回分成不重疊的完整循環；開場可能是過渡，故不只從第 0 格搜尋。多個相位分法先比較完整段數，再比較平均首尾及鄰格匹配分數，同分取較早分法；選定分法後逐段評分擇優，不能以跨過中間返回的長區間替代單段。`cycle_candidates` 保存每段 start、end、matching_tail、score 與 seam_distance，`complete_cycle_count` 是該分法辨識出的完整段數，不是要求影片生成幾次的設定。只辨識到一段就評估該段；尾端未完成的演出不計入。無可靠完整返回時回 needs_review，不能把任意相似頭尾當成已數完循環。這是數值候選，仍須檢查是否實際構成完整動作。選出幾段與交付 GIF 無限重播是不同事項。

選段分析可使用獨立 Python 的 BiRefNet 模型遮罩，透過 selection.foreground 明確指定模型目錄及裝置，安裝與入口見[環境設定](setup.md#選段分析用的本機人物遮罩)。先在較高解析度辨識主體，再縮成動作特徵；不透過 ComfyUI。遮罩及來源影格索引保存在 analysis-masks/analysis.json，須檢查牆地交界殘留、腳部完整及跨幀穩定性；模型輸出不等同已通過品質檢查。這只改分析特徵，不平移、縮放或刪除交付影格。未配置模型時，Loop 的簡單背景分析逐列參考兩側背景、再取主連通前景；它可能保留與人物相連的交界線，不能當作通用去背。

`return_to_start` 以完整來源幀率的低解析度主體特徵分析，排除與最大連通主體分離的特效區塊。先將接近開場基準的穩定段辨識為返回區域；中間沒有顯著動作的相鄰區域合併，兩次相鄰返回區域間的顯著離開與返回各成一個候選，避免把多次演出合成一段。每段從前一返回區域末端，取至下一穩定返回區域內首次符合起點姿態容差的影格，不延伸到較晚才出現的更相近姿態。比較首尾差異除以段內最大姿態差異的分數，較低者優先，同分取較早一段；`return_candidates` 保存各段區間、首尾差異、動作幅度及分數。返回容差隨來源動作幅度調整並有上限，不能把稍微不同的收招一律排除。沒有可辨識的穩定返回區域時，才退回相似姿態候選。這些是影像特徵候選而非語意品質保證；連在身體上的特效、低對比斷裂與鏡頭變化仍可能干擾，需檢查是否完整出招及收招。Loop 與 hold_end_pose 保留原有分流。

Python 的 `select_segment.py` 以低解析度數值分析提出候選，並保存 `auto-segment.json`。`status=selected` 不等於視覺通過。無明確結果時，Codex 檢查必要的候選預覽並指定 `--start`、`--end`；不可套固定秒數或所有影片共用同一區間。索引從 0 起算，包含 end。手動 loop 的 end 也應已排除重複接點，程式不再減一次。

### hold_end_pose 的 X 與 Y

B 的判斷用穩定程度及主要動作的開始，不由自適應補幀分數推導。程式以相鄰穩定段之間、超過穩定門檻的運動能量比較活動區段，選主要活動前的穩定段末端作 B；不直接選離 D 最近的小幅收尾。分析保留來源格精度，`activity_episodes` 保存候選區段與分數供核對。Y 明確為 B..D，不能把前段 A 混入 Y，再由去重間接刪掉 A..B 的演出。這套 X＋Y 規則適用所有 `hold_end_pose` 任務，不依動作名稱分流。

Codex 在 Refine 前檢視 B 之前必要的局部候選，辨識有意義前段演出的起點 A；排除開場 Idle、姿態準備及無關等待。這是內容判斷，不按動作名稱分流，不要求 Codex 逐幀看完整影片。自動選段的 `lead_candidate_range` 只是待檢查範圍，不能直接當 X。

- 有 X：明確給 `--lead-start A --start B --end D`，X 為 A..B−1，Y 為 B..D，B 只出現一次。
- 沒有 X：檢查後明確給 `--lead-start B`。省略時仍可輸出 Y，但 `sampling.lead_review_required=true`，Codex 不可因此略過前段檢查或直接標記交付完成。
- X 保留少量小動態。時間分箱先選代表姿態，再將顯著變化補在原時間箱內；確實靜止時只留一張代表格，不用重複圖填滿張數。`--lead-refresh-ms` 預設 160，控制代表圖的取樣節奏，並非固定 X 時長，可依選中預覽調整。數值不是跨素材品質保證。
- `--count` 若指定，只控制 Y 張數，X 另計；不把 X 擠入主要動作的張數預算。

```text
python scripts/spritesheet.py source.mp4 --motion-type hold_end_pose --lead-start A --start B --end D --seconds 1 --scale RESTORE_SCALE --output work/action/selection
python scripts/finish_animation.py source.mp4 --motion-type hold_end_pose --lead-start A --start B --end D --seconds 1 --scale RESTORE_SCALE --image-profile .local/image-profile.json --job work/action/finish-job --output outputs/action --prompt-file work/action/refine-with-effects.txt --remove-effects-prompt-file work/action/refine-without-effects.txt
```

## 依動作類型選幀與保留節奏


`loop` 與未指定類型的手動區間維持等距取樣；跳躍拆出的上升、下落段也維持各段等距，見[空中處理](airborne.md)。

`return_to_start` 與 `hold_end_pose` 的 Y 使用 `scripts/frame_sampling.py`，地面與空中共用：

1. 在已確認區間，以來源幀率解碼低解析度數值特徵；不是把整段送去圖片編輯或 Codex 逐幀判讀。移除區間共同靜態特徵，忽略不大於 4 的特徵強度差，以減少不變身體與微量雜訊稀釋局部動作。
2. 先保留頭尾。return_to_start 另保留主體輪廓向左右上下顯著超出兩端的伸展位置，作為補幀分割的錨點；這是輪廓極值而非人體關節追蹤，仍需確認主動作。明確 count 的預算包含這些錨點，不超額補幀。對每個相鄰已選區間，計算內部格與左右端點的正規化差異，兩者較小值是補幀價值；選最大的候選分割區間，再遞迴比較。相同分數以鄰格變化與時間位置決定順序。
3. 當所有局部候選分數均不超過門檻便停止，不會每次呼叫都強制補一格。`--quality compact`（預設）門檻 0.75，`balanced` 0.60，`smooth` 0.45；較低門檻選得較密。這些是經素材測試的操作預設，不是動作品質、人體軌跡或成功機率。
4. 明確指定 `--count N` 時改為指定張數，仍按同一分割優先順序補選，保留首尾；僅在使用者要求或實際檢查有依據時使用，不能再次一律固定 8 格。來源張數不足即停止，不複製影格湊數。

演出效果可提供出力線索，數值分析不一律排除它；特效、衣物、鏡頭與位移也可能干擾。空中取樣在腰部定位之前，須確認沒有只追隨垂直移動而漏掉肢體。這不是主要目標追蹤器，不能保證自動分辨主動作與伴隨動作。

### Refine 前的少量視覺檢查

先用 `spritesheet.py` 輸出 `selection.json` 與 `cropped/`，檢視選中影格及必要的局部候選：

- 區間涵蓋起手、主要展開與收招；動作結束符合類型。
- 快速過程與必要中間姿態仍可讀；不是多張近似姿態佔位卻漏掉主要過程。
- 去掉效果後角色與裝備本身能交代動作；X 是有意義演出而非前置準備。
- X 小動態、主要動作與接點節奏合理；預覽逐支獨立觀看，避免拼成同步比較動畫干擾判讀。

先修正區間，再按證據調整 quality、X 取樣節奏或明確張數，不改共用程式遷就某支素材。確認後由執行計畫將同一份 selection_file 交給 finish，不重新取樣。手選索引直接填入 selection args 的 indices 與 frame_durations_ms，不寫臨時匯入呼叫程式。CFR／VFR 的來源時間與覆蓋權重由既有時間程式處理。

### 共用來源時間倍率

曲線方法的補幀及刪幀使用 `max(曲線近似誤差, 有序停格誤差)`，兩者皆須符合相同 quality 容差。有序停格誤差先以來源 PTS 加權，找出相鄰代表格間總姿態差異最小的時序分界（與時間分配一致），再量測每個來源格與它實際歸屬的代表格的最大差異；不是只找任一較近端點，也不是把不存在於成品的插值圖當作已顯示。`selection.error_model` 與 `interval_errors` 保存誤差模型、各區間兩種誤差及分界，供診斷停止／刪除原因。此判準評估量化前的來源時間分配；GIF 20ms 取整仍可能造成時間偏差，需另核對時間表。顯著誤差被允許才檢討門檻，動作變化未被誤差反映則檢討特徵／公式，不用單支素材的保護點代替修正。

曲線方法只以起終點界定區間，不自動加入輪廓極值或主要姿態錨點。在自動補幀後再作刪幀驗證：逐一計算刪除中間格後整個合併區間的最大來源近似誤差，只有仍符合相同 quality 容差才可刪除；每次刪除可行候選中誤差最低者，重算鄰接關係，直到無格可刪。明確 count 不作此刪減。`selection.pruning` 保存初始張數、實際刪除格及合併誤差；時間在刪減完成後統一分配，不指定目標張數，也不宣稱找到全域最少格數。

可透過正式 selection 參數 `sampling_method` 比較 `novelty`（預設）、`linear`、`cubic`。後兩者以來源 PTS 為自變數，對遮罩內 RGB 活動特徵作線性或三次 Hermite 近似；立方切線取相鄰來源格的時間差分，預測值限制在合法亮度範圍。計算實際特徵與預測特徵的整體正規化誤差，遞迴加入誤差最大的來源格，沿用 quality 門檻及區間端點。此法近似的是影像特徵，不是人體關節曲線，不保證保留語意動作。曲線近似誤差只衡量假設連續插值的重建，不能直接當作逐格停留播放的充分品質判準；診斷須另核對來源中間格與實際代表格的差異，不因曲線誤差合格就宣稱動作覆蓋合格。成品仍逐格顯示來源圖片，沒有立方補間。比較時固定來源、區間規則、quality、尺度、總時長及後處理，只改 sampling_method；須檢查來源運動覆蓋及最終 GIF，不能以較少格數宣稱較好。使用曲線方法需安裝 requirements 中的 NumPy。

主體特徵保留遮罩內的 RGB 色彩與暗部差異；Alpha 負責排除背景，不以固定高亮度下限抹平人物內部。X 小動態補幀由獨立 LeadScorer 比較整體及固定分區差異，分區正規化以整體平均分區能量作分母下限，避免空白區微量雜訊被放大。此敏感度僅用於 X，不套到 Y 選幀、曲線誤差或姿態時間分配；這三者使用整體主體活動特徵，不取局部最大誤差。Y 的目標是保留主要動作過程，X 的目標是保留前段小動態，不能互相替代。這項界線修正不代表已驗證 Y 的精簡品質；Y 仍依來源對照與數值證據評估。不辨識拳腳、不固定每段格數，沿用既有 quality 門檻。最終動作檢查須對照來源，確認主要展開與回復過程仍被保留，不能只核對起點、極值及終點；靜態相似度達標不等於主觀動作合格。

Y 的每張代表格按主體姿態相似度承接來源時間：在相鄰代表格間找出維持時序且總差異最小的分界，使用來源 PTS 加權。持續姿態的時間歸給相似代表格，避免短暫過渡格因時間中點切分而承接前後停留。`timing_assignment.source_bins` 保存來源覆蓋區間；不依動作名稱、肢體或最大伸展位置指定最長停留。

選幀密度與時間分開。`source_clock.py` 讀來源影格 PTS 與最後一格長度；X 時間為 t(B)−t(A)，Y 為 t(D+1)−t(B)。只使用有效 A..D，不把排除的 Idle 或過長尾端停留算進比例。沒有 X 時使用 B..D。

整段依 `--seconds` 使用一個倍率。GIF 採 20 ms 網格，要求秒數向下取至此網格；X 按比例向下取整，不超過其比例時間，餘數給 Y。每格至少 20 ms，補選只分攤原時間，不增加 X、Y 或總長。時間不足容納影格時停止，改選較省格策略或依使用者時間需求處理，不能暗中拉長動畫。來源 X 本身很長時，其占比仍會保留，比例規則不等於自動改善來源演出。

`animation.json` 的 `sample_indices`、`frame_durations_ms` 與影格表順序對應，`sampling` 保存局部分割分數、停止原因、來源時間、X/Y 分界及預算。GIF 使用同一時間表；Refine、去背、裁切與空中腰部定位不得重選或改寫時間。交付時提醒使用者在引擎使用逐格時間，否則等時長播放會改變非等距選幀的節奏。直接檢查既有檔案與時間表，不要求瀏覽器播放紀錄；靜態檢查不冒稱已實際播放。

## 選幀後的鏡頭補償

地面來源有可辨識的固定背景交界且觀察到垂直漂移時，依[背景鏡頭補償](camera-alignment.md)先處理選中影格，再進入裁切與 Refine。沒有可靠背景時不以腰部、腳底或輪廓中心替代；空中腰部定位另依其專屬流程。

## 裁切、Refine 與合併

`--scale` 預設 1，是所有選中影格的統一縮回倍率。後端不讀取前端基準框、站姿或留白設定。使用者直接提供影片而需要限制交付格子大小時，可另用 `--max-side`；按既定角色尺度縮回時省略它。

尺度核對分成兩件事：程式倍率是否一致，以及來源／影像編輯是否改變身體尺度。站立、彎曲、橫躺會改變外接框，頭髮與裝備也會影響邊界，不能用最大邊或輪廓框重新歸一化。疑似變小時，選少量同源影格依序比較「來源套用 frame_scale → 第一次裁切輸入 → Refine → 最終影格」，以共同顯示倍率對照身體部位；核對 first_crop.scale、refined_crop.scale、delivery_scale 及工作流輸入輸出尺寸，定位變化發生階段。來源已存在的比例變化應在來源檢查處理，Refine 新增的變化則修正該影格；不以逐格縮放掩蓋來源問題，也不以相同倍率數字代替身體尺度的實際檢視。

### 共用影像編輯與版本提示詞

先檢查選中來源。可由 Alpha 排除的效果直接去背；殘留、重疊或色彩污染才用 Refine 清理，再重新計算 Alpha。正常流程只生成 clean 成品。

Refine 的單一提示詞描述實際要移除的效果與須保留的角色、姿態及裝備。Refine 保持背景，去背由獨立遮罩處理。

共同段版型：

> 清理這張角色動畫影格，修復角色與實體裝備的動態模糊，恢復符合原繪製風格的清晰輪廓與細節。保留角色身份、服裝、配件、實體裝備、朝向及當前動作姿勢，保持角色尺度、畫布內位置與畫布尺寸不變。保留可見肢體、裝備的細長輪廓與尖端，以及手部握持關係。保持原背景，背景透明度由後續專用遮罩處理。

有特效版附加段：

> 保留來源已有的視覺特效及其位置、形態、色彩、層次與透明過渡；特效是需保留的前景內容，不當作背景刪除。只修復角色與實體裝備的模糊，不將特效自身的柔和或半透明表現改成硬邊，也不新增或擴大效果。

#### 去特效第一關：共用版型批次處理

Codex 檢視已選影格總覽，辨識附加特效、實體道具及兩者容易混淆的部位，填入下列效果處理段，再接上共同段。固定句型，變數依素材填寫；同組素材共用，不逐張重新撰寫，也不另設先小量驗證才批次執行的階段。

> 移除圖像中附加的【特效特徵】，清除效果覆蓋造成的灰霧與亮度、色彩污染；這些附加效果不屬於實體裝備。保留【實體道具】，包括【必須保留的部位】及其原有材質反光。

- `特效特徵`：填入來源可見的色彩、形態及伴隨層次，包含需移除的半透明填充；不只填「所有特效」，也不將特定動作綁定到固定效果。
- `實體道具`：填入角色實際穿戴或握持的物件；沒有道具時省略道具句，不虛構物件。
- `必須保留的部位`：填入易與特效混淆的實體輪廓、端點、結構或連接關係；角色自身的設計若容易混淆，也在保留句中指出。

括號內容由 Codex 依已選影格填妥後才送出，不把欄位交給使用者撰寫。辨識與處理僅限已選影格，不回頭逐幀分析整段影片。

#### 去特效第二關：檢查與精準修正

第一關完成後，Codex 對照原始已選輸入與 Refine 結果，逐張檢查：附加效果及污染是否殘留、角色或實體道具是否誤刪、姿勢與握持關係是否改變、背景是否真正透明且沒有雜訊。保留合格結果，只處理未通過影格，不重新選幀或重跑整批。

直接使用既有影格表、來源與輸出原圖及數值疑點清單，不另外產生審查總覽或比較圖；有疑點才讀取相關原檔。輪廓差異只能協助排序，不能判定特效已移除或角色身份一致。

針對殘留，指出「是什麼、在哪裡、如何與實體區分」，以此補充第一關完整提示詞；不是只增加「徹底」「完全」等強調詞。第二關補充段置於原提示詞之前：

> 需要移除的附加效果是【殘留外觀】，位於【相對位置與延伸範圍】。這部分是【效果的性質】，不是【容易混淆的實體內容】。保留【實體部位及其位置、結構與連接關係】。

位置使用該張圖可辨識的角色、道具或畫布作參照，明確指出延伸範圍；不將該張圖的方向、道具名稱或效果形態固化成通用規則。若發現實體誤刪，對照原輸入補充被刪部位及其連接關係。透明背景異常也列為未通過，不把淡化殘影或帶雜訊的背景當成已去乾淨。

每個未通過影格使用第一關的同一張 `refine/NNN/input.png` 重新處理，保持裁切、縮放與補邊一致；不編輯第一關輸出，避免累積細節流失。修改提示詞後建立獨立圖片任務目錄，以既有圖片入口執行：

```text
python scripts/process_image.py --profile .local/image-profile.json --image work/action/finish-job/without_effects/refine/NNN/input.png --prompt-file work/action/corrections/NNN/prompt.txt --job work/action/corrections/NNN/image-job
```

Codex 開啟修正結果，重新檢查原缺陷及角色、道具、姿勢、尺寸、透明背景；通過才採用。尚有缺陷時，以當前可見缺陷更新辨識描述，沿用同一原始輸入再處理；不把圖片任務完成當成檢查通過。

修正結果通過檢查後，將要採用的檔案列入 JSON。鍵為版本及原始來源影格索引，不是選格順序；`image` 是第二關圖片工作流回傳的原尺寸（含原補邊）PNG，`prompt` 是實際送入的完整提示詞。相對路徑以此清單所在資料夾解析：

```json
{
  "without_effects": {
    "SOURCE_INDEX": {"image": "accepted-result.png", "prompt": "precise-prompt.txt"}
  }
}
```

將 `SOURCE_INDEX` 換成實際數字字串，可一次列多張或兩個版本。只列已檢查通過的修正；不將失敗結果列入採用清單。

```text
python scripts/apply_corrections.py --summary outputs/action/variants.json --corrections work/action/corrections/accepted.json --job work/action/correction-assembly --output outputs/action-corrected
```

使用新的任務與輸出目錄，不覆寫已交付版本。程式先檢查所有替換的來源索引、尺寸、Alpha 及提示詞，再採用指定結果，重用其他已合格 Refine，不提交任何圖片工作流；裁回原補邊後重算第二次共同裁切、最終影格、影格表、GIF、錨點與倍率、成品 JSON 及 `variants.json`。來源索引、順序與逐格時間保持不變。完成後依交付檢查核對新成品，角色計畫及打包 manifest 改指向新的輸出。

地面與空中動作使用同一入口。跳躍兩段必須將 `--summary` 指向完整 `jump.json`，不能只修其中一段；程式從 `joint_summary` 取得選格聯集，處理後依原分界重建兩段，各版本的共用接點使用同一修正結果及共同裁切，保留原有段落時間。空中基準 profile 不因後段修正而重建。

每版 `refinement` 的 `correction_prompt` 記錄該張實際採用的第二關提示詞。打包時會自動封存並改為 ZIP 內的相對路徑，來源索引仍在該筆記錄中；第一關提示詞亦保留。不要另寫腳本手動拼表或只替換影格表上的單格。

正常執行由 execution_plan 串接已確認的選幀，輸出 clean 與 variants.json 摘要。

Python 只分析選中影格，從各格外框取樣估計實際純色背景，再依色差閾值取得內容範圍；預設閾值為各 RGB 通道最大差 32，可用 `--background-tolerance` 調整。

第一次共同裁切以統一縮放後的畫面中線為水平中心，左右對稱容納所有選中影格的內容，上下涵蓋共同範圍。所有影格以相同座標裁切並保存至任務目錄 `cropped/`；此時視覺效果也可能包含在裁切範圍內。

裁切後依原順序逐張執行圖片工作流，使用該版完整提示詞同時進行 Refine、去背與該版效果處理。各張任務位於各版本的 `refine/000/image-job/` 等獨立目錄，保存輸入、工作流、任務狀態及結果。圖片尺寸倍數由 profile 的 `input_alignment` 決定，只在每張右側、底部補原背景，處理後裁回原尺寸，不改變角色位置與尺度。

每張結果必須保持送入尺寸、具備真正透明背景與有效可見角色；尺寸變更、不透明或空白結果會停止處理，不自動跳過。用相同命令與任務目錄重跑可重用已完成的逐張工作流，接續未完成任務；輸入、提示詞或 profile 變更時須使用新任務目錄。提交沒有取得 ID 時，先查佇列，不直接重送。

Refine 與專用去背完成後先清除低 Alpha 殘值，再計算第二次共同裁切。`--alpha-cutoff` 預設為 8：Alpha 小於 8 清為 0，8 以上保留原本漸層與 RGB，不強制二值化；設為 0 可停用清理，合法範圍為 0～255。含極淡半透明設計的角色或保留特效版需檢視原始 Refine 結果，必要時降低門檻，避免把需保留的淡效果刪掉。所有影格清理後以非零 Alpha 範圍計算共同裁切框，完整容納保留下來的邊緣；若最終縮放重新產生低 Alpha 像素，交付前會再次以同一門檻清理。原始 Refine PNG 保留不變，清理作用於最終影格。以原裁切畫布中線為水平中心，左右對稱，上下涵蓋所有角色內容；每張使用相同座標，不逐幀置中、貼底或縮放。若指定 `--max-side`，只在此時使用共同倍率限制最終尺寸。最後各張底部補 1 px 透明邊，保存至 `final-frames/`，再合併影格表。

1 至 6 格單排，7 至 12 格雙排，13 格以上每排最多 6 格並增加排數。順序為左至右、上至下，未用格子透明。

成品存於 output/clean/，包含 spritesheet.png、preview.gif 與 animation.json。variants.json 保存來源索引與逐格時間。

第二次共同裁切使用所有成品影格。anchor_px 與 delivery_scale 保存共同座標，地面採 source_origin，空中採 waist。

對照來源選幀與 clean 成品，確認特效清除、姿勢與裝備保留、人物尺度和相對位置一致。

### 素材包與聊天展示

由 execution_plan 的 package 封存來源、原始選幀、提示詞與 clean 成品。依序展示來源影片、GIF、影格表及 ZIP。

本次交付結束後，提示可直接說「再來我想要產生 XXX 動作」。這屬於下一次操作，不穿插於 GIF、影格表與 ZIP 之間；ZIP 最後指交付項目的順序，不限制整則訊息的最後一段。

使用實際可取得的絕對媒體路徑或有效下載入口，不只寫檔名。GIF 的二值透明不代表 PNG 的半透明已丟失，透明邊緣品質仍以 PNG 檢查。畫面呈現順序不得因先完成無特效版而反轉。



## 完成與交付驗證

### 檢查紀錄

各任務在自己的工作目錄保存 `review.md`，記錄目前有效的檢查結論；重做後更新當前結論，不累積修改歷史。角色參考準備也使用相同格式。這是 Codex 的檢查紀錄，不是後段腳本必填輸入，也不要求既有影片使用者補建前段紀錄。

```text
任務／階段：本次任務識別與檢查階段
檢查對象：實際檔案路徑；涉及選幀時列原始影格索引
項目 | 結果（pass / fail / pending / n/a） | 證據與判斷
下一步：未通過或待檢項目的處理；全部通過則寫可進入的下一階段
```

依實際階段列項，不抄一張全部通過的空泛清單：參考階段記錄姿態、外觀、完整性、透明與共用幾何；影片階段記錄演出、結束行為、節奏及超框／遮擋；空中定位階段記錄腰部匹配與位移；交付階段逐項記錄下列三類完成條件。證據可引用程式報告、實際檔案、接點或選中影格的具體觀察。視覺項目須實際開啟對應圖片或預覽，不以程式回報代替；尚未看過寫 `pending`，不適用寫 `n/a` 並說明原因。使用者已確認的項目註明確認內容；不為填表新增使用者問答。

只有本次必要項目均為 `pass`，其餘均有合理的 `n/a` 原因，才能宣告該階段通過。局部通過不代表整項完成。完成交付驗證後，可在角色計畫的 artifacts 另以 `review` 指向紀錄；沒有角色計畫時仍保存於本次工作目錄。

### 完成條件

程式回報成功、檔案存在或 JSON 中的 `verified` 均不能單獨代表任務完成。Codex 須在標記 `completed` 前完成以下檢查：

1. **格式與規格**：來源影片可讀，實際交付版本的 PNG、GIF、JSON 及摘要均可開啟；成品來源索引、順序及逐格時間與選幀結果一致，影格數、排列、格子尺寸、播放時間、動作類型及來源索引符合本次任務，JSON 路徑能解析到正確素材。PNG 有真正透明背景；GIF 預覽包含動作影格並設為無限重播，不可只播放一次。
2. **視覺品質**：依上文對照選中的來源影格、原始 Refine 與最終影格，檢查動作完整性、角色及裝備保留、透明邊緣、尺度與位置；循環接點或動作結束方式符合所選類型。只針對選中影格檢視，不將整段影片的所有來源影格送去 Refine 或視覺逐幀判讀。
3. **交付完整性**：確認實際版本 PNG、GIF、JSON、合併前最終影格與 ZIP 實際存在且可供使用者取得；ZIP 可正常解壓，包含本任務實際使用的必要素材、提示詞與成品，封存內 JSON 路徑可使用。依上節固定順序展示 GIF 與 PNG，最後提供 ZIP 的有效路徑或下載入口。

打包前，程式另核對每張最終 PNG 與影格表對應格像素一致、GIF 與最終影格的畫面順序及時間一致、預覽尺寸與無限重播設定正確，並保存實際修正提示詞。

程式負責可機械檢查的格式、尺寸、Alpha、時間與封存完整性；Codex 負責動作意圖、視覺品質及交付內容的確認。任一必要檢查失敗或尚未完成，保留 `needs_review` 並說明待處理項目，不以檔案存在代替完成。全部通過並打包後，由執行計畫同步角色任務完成；直接提供影片而沒有角色計畫時，仍遵守相同交付條件。

最終聊天交付先嵌入來源影片原檔供使用者播放，再依要求展示 GIF、PNG 與 ZIP。處理中的檢查不開瀏覽器、不展示中間畫面，只回報文字進度。
