# 影格表與預覽

確認成品播放時間與本次統一縮放倍率。成品預設 8 格，依動作複雜度增加，不設固定上限。

本段只需要來源影片、圖片工作流設定、Refine 提示詞與明確處理參數，可直接處理使用者提供的影片，不讀取前段的角色版面、生成提示詞或內部設定。先檢視來源區段，確認角色與裝備的完整內容仍可辨識；半透明效果覆蓋不直接判定失敗，但被強光或不透明效果完全取代的內容不保證能重建。遇到這種影格，選擇其他完整區間或回報需要替換來源，不在後段重新設計角色或生成動作。

Codex 依動作完成後的行為指定 `--motion-type`。這三種類型描述動作內容，與 GIF 預覽是否重播無關：

| 類型 | 參數／英文名稱 | 定義與自動選段 |
| --- | --- | --- |
| 循環動作 | `loop` / Loop | 動作末尾直接銜接開頭，可持續重播。找近似首尾，取頭至尾−1，省略重複尾格。 |
| 返回起始動作 | `return_to_start` / Return to start | 從指定起始基準出發，完成一次動作後回到同一基準；每次觸發播放一次，可再次觸發。找近似起手與回復姿態，取頭至尾，保留兩端。 |
| 保持結束姿態動作 | `hold_end_pose` / Hold end pose | 完成一次動作後保持目標結束姿態，不要求返回起始基準。先找末端穩定段，再向前找最後一段起始穩定段，取頭至尾。 |

可再次觸發不等於自動循環播放。「起始基準」由明確的動作環境決定：地面使用對應 Idle，空中使用對應空中姿態；不是固定取來源影片第 0 格。來源完整演出的開頭也不等於每段交付片段的開頭。`hold_end_pose` 保留完整動作與穩定結束姿態，不要求在影格表中複製多張末幀來模擬停留。

Python 使用低解析度影格比較姿勢、運動與穩定程度，不依賴前端設定或動作名稱。保持結束姿態動作頭取起始穩定段最後一格，尾取末端穩定段第一格；排除自然站立與姿態轉換。循環需包含實際運動，不能把靜止片段當成循環。

```text
python scripts/finish_animation.py source.mp4 --motion-type loop --scale 0.5 --image-profile .local/image-profile.json --job work/action/finish-job --output outputs/action --prompt-file work/action/refine.txt --count 8 --seconds 0.8
```

自動選段資料存入工作目錄 `auto-segment.json`。無明確結果時，Codex 檢視影片，明確傳入 `--start`、`--end` 覆寫區間，不固定排除幾秒。兩者均為從 0 起算且包含 end 的影格編號。程式在區間內等距選出所需張數；循環動作省略重複尾格，其餘保留兩端。GIF 預覽無論動作類型一律無限重播；JSON 的 `loop` 布林值描述循環選段方式，不控制 GIF 播放。手動指定區間且未提供 `--motion-type` 時，`--loop` 只控制循環取樣，也不控制 GIF 播放。

`--scale` 預設 1，是所有選中影格的統一縮回倍率。後端不讀取前端基準框、站姿或留白設定。使用者直接提供影片而需要限制交付格子大小時，可另用 `--max-side`；按既定角色尺度縮回時省略它。

將 Refine 提示詞存為 UTF-8 檔案。提示詞應要求清除影片額外生成、最終角色動畫不需要的視覺效果，修復動態模糊及角色輪廓與細節，並同時移除背景、輸出真正透明 PNG。半透明覆蓋區需去掉造成的灰霧、亮度及色彩污染，恢復仍可辨識的角色內容。保持原影格的角色外觀、繪製風格、朝向、姿勢、配件、尺度、位置與畫布尺寸；依素材辨識多餘內容，不將特定效果或動作寫成程式規則。武器、握柄及其原有裝飾屬於實體裝備，與待移除效果分開辨識，保留完整刃線、尖端、握持關係與表面細節。不要移除角色本身的設計元素，也不要改變肢體姿勢或新增細節。

可依素材調整下列提示詞：

> 清理這張角色動畫影格，移除額外生成的視覺效果與背景，清除半透明覆蓋造成的灰霧、亮度與色彩污染；修復動態模糊，恢復清晰且符合原繪製風格的輪廓與細節。保留角色身份、服裝、配件、實體裝備、朝向及當前動作姿勢，保持角色尺度、畫布內位置及畫布尺寸不變。保留可見肢體、裝備的細長輪廓與尖端，以及手部握持關係。輸出保留完整角色與半透明邊緣的透明背景 PNG。

Python 只分析選中影格，從各格外框取樣估計實際純色背景，再依色差閾值取得內容範圍；預設閾值為各 RGB 通道最大差 32，可用 `--background-tolerance` 調整。

第一次共同裁切以統一縮放後的畫面中線為水平中心，左右對稱容納所有選中影格的內容，上下涵蓋共同範圍。所有影格以相同座標裁切並保存至任務目錄 `cropped/`；此時視覺效果也可能包含在裁切範圍內。

裁切後依原順序逐張執行圖片工作流，同一份提示詞同時進行 Refine 與去背。各張任務位於 `refine/000/image-job/` 等獨立目錄，保存輸入、工作流、任務狀態及結果。圖片尺寸倍數由 profile 的 `input_alignment` 決定，只在每張右側、底部補原背景，處理後裁回原尺寸，不改變角色位置與尺度。

每張結果必須保持送入尺寸、具備真正透明背景與有效可見角色；尺寸變更、不透明或空白結果會停止處理，不自動跳過。用相同命令與任務目錄重跑可重用已完成的逐張工作流，接續未完成任務；輸入、提示詞或 profile 變更時須使用新任務目錄。提交沒有取得 ID 時，先查佇列，不直接重送。

Refine 後先清除低 Alpha 殘值，再計算第二次共同裁切。`--alpha-cutoff` 預設為 8：Alpha 小於 8 清為 0，8 以上保留原本漸層與 RGB，不強制二值化；設為 0 可停用清理，合法範圍為 0～255。含極淡半透明設計的角色需檢視原始 Refine 結果，必要時降低門檻。所有影格清理後以非零 Alpha 範圍計算共同裁切框，完整容納保留下來的邊緣；若最終縮放重新產生低 Alpha 像素，交付前會再次以同一門檻清理。原始 Refine PNG 保留不變，清理作用於最終影格。以原裁切畫布中線為水平中心，左右對稱，上下涵蓋所有角色內容；每張使用相同座標，不逐幀置中、貼底或縮放。若指定 `--max-side`，只在此時使用共同倍率限制最終尺寸。最後各張底部補 1 px 透明邊，保存至 `final-frames/`，再合併影格表。

1 至 6 格單排，7 至 12 格雙排，13 格以上每排最多 6 格並增加排數。順序為左至右、上至下，未用格子透明。

輸出為 `spritesheet.png`、`preview.gif`、`animation.json`。規格包含來源影格索引、統一縮放倍率、第一次裁切、逐張處理素材與補邊、第二次 Alpha 裁切、`refined_crop.alpha_cutoff` 及最終格子尺寸。兩次裁切框分別使用縮放後影片與 Refine 畫布的座標。成品播放時間獨立於來源影片速度；GIF 以 10 毫秒為單位分配時間，Alpha 小於 128 的像素設為透明，其餘不透明，PNG 保留完整 Alpha。

Codex 最後對照選中來源、原始 Refine 及 Alpha 清理後成品，確認多餘效果已移除、模糊已修復，並檢查姿勢、外觀、尺度及位置的一致性。武器須逐格確認刃線、尖端、握柄與手部連接沒有被當成特效刪除；細髮、飄帶與半透明設計也須比較 Alpha 清理前後。程式尺寸與 Alpha 檢查不能代替視覺檢查；發現漂移時調整提示詞並在新任務中處理，不以逐幀重新定位掩蓋問題。若缺失已存在於原始 Refine，調整圖片編輯提示詞；若僅發生於低 Alpha 清理後，降低 `--alpha-cutoff` 並重製，不需要重新生成影片。

多個動作各自選區間、計算裁切框，使用獨立工作目錄與輸出目錄執行完整流程。每個動作各交付一張透明影格表與一張透明 GIF。

交付時以 `scripts/package_delivery.py --manifest assets.json --output delivery.zip` 打包；清單明確提供 `video`、`animation`（成品 JSON）及 `files`（封存內相對路徑對應素材路徑）。收集上傳圖、實際使用的姿態參考及 Idle 基準影格、影片輸入與提示詞，程式匯出全部與選中原始影格，並自動封存第一次裁切影格、逐張工作流輸入、Refine 透明影格、最終裁切影格及成品。實際 Refine 提示詞需由 `files` 明確收錄，例如 `"prompts/refine.txt": "work/action/refine.txt"`。只收集實際使用的素材，不猜前端目錄。聊天中直接展示 GIF 與透明影格表，附 ZIP 下載。

## 完成與交付驗證

### 檢查紀錄

各任務在自己的工作目錄保存 `review.md`，記錄目前有效的檢查結論；重做後更新當前結論，不累積修改歷史。角色參考準備也使用相同格式。這是 Codex 的檢查紀錄，不是後段腳本必填輸入，也不要求既有影片使用者補建前段紀錄。

```text
任務／階段：本次任務識別與檢查階段
檢查對象：實際檔案路徑；涉及選幀時列原始影格索引
項目 | 結果（pass / fail / pending / n/a） | 證據與判斷
下一步：未通過或待檢項目的處理；全部通過則寫可進入的下一階段
```

依實際階段列項，不抄一張全部通過的空泛清單：參考階段記錄姿態、外觀、完整性、透明與共用幾何；影片階段記錄演出、結束行為、節奏及超框／遮擋；空中定位階段記錄腰部匹配與位移；交付階段逐項記錄下列三類完成條件。證據可引用程式報告、實際檔案、接點或選中影格的具體觀察。視覺項目須實際開啟對應圖片或預覽，不以程式回報代替；尚未看過寫 `pending`，不適用寫 `n/a` 並說明原因。使用者已確認的項目註明確認內容；不為填表新增使用者問答。

只有本次必要項目均為 `pass`，其餘均有合理的 `n/a` 原因，才能宣告該階段通過。局部通過不代表整項完成。完成交付驗證後，可在角色計畫的 artifacts 另以 `review` 指向紀錄；沒有角色計畫時仍保存於本次工作目錄。

### 完成條件

程式回報成功、檔案存在或 JSON 中的 `verified` 均不能單獨代表任務完成。Codex 須在標記 `completed` 前完成以下檢查：

1. **格式與規格**：來源影片可讀，PNG、GIF、JSON 均可開啟；影格數、排列、格子尺寸、播放時間、動作類型及來源索引符合本次任務，JSON 路徑能解析到正確素材。PNG 有真正透明背景；GIF 預覽包含動作影格並設為無限重播，不可只播放一次。
2. **視覺品質**：依上文對照選中的來源影格、原始 Refine 與最終影格，檢查動作完整性、角色及裝備保留、透明邊緣、尺度與位置；循環接點或動作結束方式符合所選類型。只針對選中影格檢視，不將整段影片的所有來源影格送去 Refine 或視覺逐幀判讀。
3. **交付完整性**：確認 PNG、GIF、JSON、ZIP 實際存在且可供使用者取得；ZIP 可正常解壓，包含本任務實際使用的必要素材、提示詞與成品，封存內 JSON 路徑可使用。展示預覽並提供成品及 ZIP 的有效路徑或下載入口。

程式負責可機械檢查的格式、尺寸、Alpha、時間與封存完整性；Codex 負責動作意圖、視覺品質及交付內容的確認。任一必要檢查失敗或尚未完成，保留 `needs_review` 並說明待處理項目，不以檔案存在代替完成。全部通過後，再由角色計畫的 `mark` 記錄完成；直接提供影片而沒有角色計畫時，仍遵守相同交付條件。
